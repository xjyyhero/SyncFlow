# CSV 示例与字段说明

依据：用户于 2026-09-09 提供的 `sample-valid.csv`，以及 PRD 的金额精度与任务内去重要求。以下区分“示例事实”和“待确认规则”；文件名表明它是合法示例，但不能据此推出完整校验契约。

## 1. 示例内容

```csv
external_id,name,amount,record_date
S001,商品A,19.90,2026-01-01
S002,商品B,29.50,2026-01-02
S003,键盘-机械轴,19,2026-01-03
S004,赠品_试用装,0.00,2026-01-04
S005,"显示器, 27 英寸",1299.5,2026-02-28
```

检查结果：1 行表头、5 条数据，每条数据解析后均为 4 列；文件可按 UTF-8 解码，不带 BOM。

## 2. 字段说明

| 字段 | 含义理解 | 示例事实 | 尚需确认 |
| --- | --- | --- | --- |
| `external_id` | 外部业务标识（根据字段名推断） | `S001` 至 `S005`，均非空且互不重复 | 是否正式作为任务内去重键、长度、字符集、大小写与空格规则 |
| `name` | 记录名称，样例为商品名称 | 包含中文、连字符、下划线、空格和逗号 | 是否必填、最大长度、是否去除首尾空格 |
| `amount` | 金额 | 出现 `19`、`1299.5`、`19.90`、`0.00` 等形式 | 负数、最大值、最大小数位数、空值、科学计数法是否允许，币种与单位 |
| `record_date` | 记录日期（具体业务含义待确认） | 均为 `YYYY-MM-DD`，不含时间 | 是否必填、允许日期范围、是否接受其他格式 |

金额使用精确数值类型是 PRD 已明确的要求，数据库使用 `DECIMAL`；具体精度和小数位配置还不能仅凭样例确定。

## 3. 从合法示例得到的实现与测试依据

- 该示例的四列表头及五条记录应作为后续正常导入的测试输入。
- 金额不能仅接受“固定两位小数”的文本形式，否则会错误拒绝 `19` 和 `1299.5`。
- 金额校验不能简单要求大于零，否则会错误拒绝示例中的 `0.00`。
- 名称不能仅允许字母数字，否则会错误拒绝中文及示例中的其他字符。
- `"显示器, 27 英寸"` 是一个完整字段，双引号是 CSV 的字段包裹符；解析后的名称为 `显示器, 27 英寸`。
- 不能用简单的按逗号切分方式解析 CSV，应使用支持引号规则的 CSV 解析器。

以上结论说明应兼容这些具体样例，不表示任意字符、金额格式或日期都合法。当前只完成文件解析检查，尚未实现或运行 CSV 导入业务。

## 4. 仍待确认的契约

- 四列是否必须严格同序，是否允许额外列、缺失列和表头大小写变化。
- 各字段是否必填、长度与取值限制。
- `external_id` 是否是正式去重键，以及重复时保留哪条、跨任务是否允许重复。
- 文件是否只接受 UTF-8，是否接受 BOM、空白行和字段内换行。
- `record_date` 的业务含义与合法范围。
- 金额的精度、范围和舍入规则。
