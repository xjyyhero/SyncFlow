## 一、任务状态机

- [x] 定义 PENDING、RUNNING、RETRYING、SUCCESS、PARTIAL_SUCCESS、FAILED、CANCELING、CANCELED 全部 8 个状态。
- [x] 实现并校验全部合法状态转换（见下表）。
- [x] SUCCESS、PARTIAL_SUCCESS、FAILED、CANCELED 为终态，不再自动执行。
- [x] 每次状态变化更新 updated_at，并通过 last_error_code / last_error_message 记录原因。
- [x] 非法状态转换返回 HTTP 409，并记录日志；Worker 内部重复领取按队列协议跳过。
- [x] 正确判定全部成功、部分成功、文件级失败、全部有效记录失败和系统处理失败；预留重试耗尽进入 FAILED 的转换。

| 当前状态 | 允许转换到 |
| --- | --- |
| PENDING | RUNNING、CANCELED |
| RUNNING | SUCCESS、PARTIAL_SUCCESS、RETRYING、FAILED、CANCELING |
| RETRYING | PENDING、FAILED、CANCELED |
| CANCELING | CANCELED、FAILED |

实现、协议冲突处理与 78 项后端测试结果见[第一节交付记录](week-04-state-machine.md)。完整重试机制属于第 5 周。

## 四、优雅停止与重启恢复

- [x] 收到 SIGTERM / SIGINT 后停止领取新任务。
- [x] 通过 WORKER_SHUTDOWN_TIMEOUT_SECONDS 配置收尾时间，默认 30 秒。
- [x] 收尾超时后安全中断，置为 FAILED 或 RETRYING 并记录原因。
- [x] 停止后没有数据库仍为 RUNNING、实际已无进程执行的任务。
- [x] 重启时扫描超过超时时间的 RUNNING 任务，按明确策略恢复或标记失败。

实现、停止边界与 96 项后端测试结果见[第四节交付记录](week-04-shutdown.md)。正常停止清理所有执行中任务；数据库回写失败时明确报错并由恢复扫描收敛。
