## 一、CSV 文件读取与数据契约

- [x] 实现本地 CSV 文件读取，Worker 能访问 API 保存的上传文件。
- [x] 校验文件扩展名为 `.csv`，保留后端校验。
- [x] 接入 `MAX_UPLOAD_FILE_SIZE_MB`，默认最大 10 MB。
- [x] 仅接受 UTF-8 编码，并兼容 UTF-8 BOM。
- [x] 第一行必须是表头；使用逗号分隔，不支持自定义分隔符。
- [x] 表头必须且只能包含 `external_id,name,amount,record_date`，列顺序固定。
- [x] 忽略空行，空行不计入总记录数。
- [x] 接入 `MAX_RECORDS_PER_JOB`，默认单任务最多 10,000 行有效数据。
- [x] 所有字符串字段先去除首尾空白，再进行校验和规范化存储。
- [x] 校验并规范化 `external_id`：必填，去空白后长度 1–64，仅允许字母、数字、下划线和短横线；同一任务内大小写不敏感去重，统一大写存储。
- [x] 校验并规范化 `name`：必填，去空白后长度 1–128，保存规范化后的值。
- [x] 校验 `amount`：必填、非负、最多两位小数，不允许科学计数法；允许 `19`、`19.9`、`19.90`，存储时统一为两位小数。
- [x] 金额使用 MySQL `DECIMAL(12,2)` 存储，并验证该类型的数值范围边界。
- [x] 校验 `record_date`：必填，严格使用 `YYYY-MM-DD`，且必须是有效日期；使用 MySQL `DATE` 存储。
- [x] 拒绝 `2026/01/01`、`01-01-2026`、包含时间或日期不存在的值。

正常样例：

```csv
external_id,name,amount,record_date
S001,商品A,19.90,2026-01-01
S002,商品B,29.50,2026-01-02
```

实现与验证见 [CSV 文件读取与数据契约交付记录](week-03-csv-contract.md)。本节交付解析模块；第二节已接入真实 Worker，第三节已实现分批事务。

## 二、文件级校验、行级校验与错误记录

### 文件级校验

- [x] 文件无法读取、编码非法、空文件或只有表头、表头非法、数据行超限时，任务进入 `FAILED`。
- [x] 文件级错误写入 `sync_errors`，`row_number` 为空，不伪造行号。
- [x] 表头校验覆盖缺失、重复、顺序错误和额外字段。
- [x] 实现并验证以下文件级错误码。

| 错误码 | 场景 |
| --- | --- |
| `FILE_UNREADABLE` | 文件不存在或无法读取 |
| `FILE_ENCODING_INVALID` | 编码无法识别或非 UTF-8 |
| `FILE_EMPTY` | 文件为空或只有表头 |
| `CSV_HEADER_INVALID` | 表头缺失、重复、顺序错误或包含额外字段 |
| `FILE_TOO_MANY_ROWS` | 有效数据行超过配置上限 |

### 行级校验

- [x] 行级校验失败时写入 `sync_errors`，继续处理下一行。
- [x] 错误记录保存 `job_id`、`row_number`、`field_name`、`error_code`、`error_message`、`raw_row` 和 `created_at`，能定位问题数据。
- [x] 实现并验证以下行级错误码及字段对应关系。

| 错误码 | `field_name` | 场景 |
| --- | --- | --- |
| `ROW_COLUMN_COUNT_MISMATCH` | 空 | 列数不正确 |
| `FIELD_REQUIRED` | 对应字段名 | 任一必填字段为空 |
| `EXTERNAL_ID_INVALID` | `external_id` | 格式不符合规则 |
| `EXTERNAL_ID_DUPLICATE` | `external_id` | 同一任务内重复，包含大小写或首尾空白规范化后重复 |
| `NAME_TOO_LONG` | `name` | 超过长度限制 |
| `AMOUNT_INVALID` | `amount` | 金额非法、为负数或小数位超过两位 |
| `DATE_INVALID` | `record_date` | 日期格式错误或日期不存在 |

- [x] 每条错误使用稳定的 `error_code`，前后端及导出文件（如有）共用同一套定义；此项不额外要求实现错误导出功能。
- [x] `error_message` 使用可读的具体原因，例如“amount 不能为负数”，不只返回错误码。

实现与验证见 [文件级校验、行级校验与错误记录](week-03-validation.md)。已接入真实 Worker，并补齐合法行落库、最终统计及部分成功状态；第三节已升级为每 250 行一个事务并更新批次进度；后续章节继续完成专项验收和页面/API。

## 三、MySQL 批量写入、任务统计与最终状态

- [x] 合法记录写入 `sync_records`，失败记录写入 `sync_errors`。
- [x] 明确批量写入的事务策略；原文建议每 100–500 行一个事务，并记录实际批大小。
- [x] 单批写入失败时只回滚该批，记录失败批次和原因，不因单批失败撤销其他批次已成功写入的数据。
- [x] 保留并验证 `UNIQUE(job_id, external_id)`，作为防止重复写入的数据库约束。
- [x] 处理过程中持续记录 `total_records`、`success_records`、`failed_records`，成功数以实际提交的数据为准。
- [x] 任务最终统计和最终状态在同一个事务中更新，避免统计与状态不一致。
- [x] 所有有效数据行均成功写入时，最终状态为 `SUCCESS`。
- [x] 至少一行成功且至少一行行级失败时，最终状态为 `PARTIAL_SUCCESS`。
- [x] 文件级校验失败，或所有有效行系统写入失败时，最终状态为 `FAILED`。
- [x] 将 `PARTIAL_SUCCESS` 接入后端状态定义、查询与筛选、接口文档、前端类型和状态展示。
