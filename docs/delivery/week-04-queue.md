# Week 4 第二节：Redis 队列与异步投递

## 队列协议

| 项目 | 当前实现 |
| --- | --- |
| 队列 | Redis List，配置 REDIS_JOB_QUEUE，默认 syncflow:jobs |
| 消息 | UTF-8 字符串，内容就是 job_id（标准小写 UUID），如 123e4567-e89b-12d3-a456-426614174000 |
| 投递 / 读取 | RPUSH / BLPOP，FIFO；BLPOP 阻塞超时 1 秒后检查停止信号和扫描时间 |
| 重试次数 | 本节没有 attempt_no；完整重试调度在第 5 周实现 |
| 原子领取 | 数据库条件 UPDATE，仅允许 PENDING → RUNNING；事务提交后才处理 CSV |

沿用已有纯任务 ID 消息格式，消息不包含文件路径或业务数据。Worker 从数据库读取可信任务信息；非法 UTF-8、非标准 UUID 消息丢弃并记日志，不回显原始消息。不存在或非 PENDING 的任务跳过。

## 创建与确认

1. API 校验上传，保存文件并刷盘。
2. 在一个 MySQL 事务中保存 PENDING 任务及 QUEUE_DISPATCH_PENDING 标记，提交后才投递 Redis。
3. RPUSH 成功后清除待确认标记，返回 201，不等待 CSV 解析与写入。清除标记失败仍返回 201，避免误导客户端重复上传。
4. RPUSH 失败返回 500。沿用第一节合法状态协议，将仍为 PENDING 的任务取消，记录 QUEUE_DISPATCH_FAILED 和错误明细；已被 Worker 领取或完成的任务不会被覆盖。

Redis List 没有独立的 ACK 命令：BLPOP 成功意味着消息已移除，**不意味着任务成功**。RUNNING 事务提交是领取确认；终态和统计事务提交是处理结果确认。业务真相保存在 MySQL，队列只通知待执行的任务。重复投递靠条件领取去重，不承诺跨 MySQL / Redis 的恰好一次消息传递。

## 定时补投

Worker 启动时扫描，之后每 30 秒在消费循环的任务间隙检查。每轮按 updated_at、id 排序，最多取 100 个超过 60 秒未更新的 PENDING 任务，重新 RPUSH 同一 job_id。

先投递，再条件更新仍为 PENDING 的任务：刷新 updated_at，并记录 QUEUE_REDISPATCHED 原因。若 Redis 失败、确认丢失或数据库回写失败，不提前刷新扫描时间，下次可重试。失败日志包含 job_id。任务已经开始或取消时，条件更新不会覆盖其状态或原因；可能多出的消息由领取检查跳过。

扫描所有超时 PENDING，包括待投递标记已经清除的任务，因此也覆盖 Redis 消息丢失和 BLPOP 后尚未领取的异常。队列中本来就有消息的慢任务可能重复入队，原子领取仍保证不会同时执行。当前扫描与处理共用 Worker 循环，长任务会推迟扫描；大规模积压时再升级带消费确认的队列，执行超时在第三节实现。

## 异常处理边界

| 中断位置 | 处理策略 |
| --- | --- |
| 数据库提交前 | 事务回滚，不投递；仅在确认记录不存在后清理文件 |
| 已提交但尚未 RPUSH / 提交响应丢失 | 数据库保留任务及文件，Worker 扫描补投 |
| RPUSH 失败且取消回写也失败 | 保留 PENDING 标记，服务恢复后扫描补投 |
| RPUSH 已成功但响应丢失 | 取消仍等待的任务；若已执行则保留结果；残留消息无法重新领取终态 |
| BLPOP 后、RUNNING 提交前退出或数据库失败 | 任务仍为 PENDING，扫描补投 |
| RUNNING 已提交后进程异常退出 | 本节不重新投递，避免与存活 Worker 并发执行；当前需人工核查，第四节实现超时识别和恢复 |
| 补投已成功但确认或标记回写丢失 | 允许再次投递同一 ID，领取时去重 |
| 扫描后并发取消 | 条件标记更新不覆盖取消原因，残留消息跳过 |

停止信号到达后扫描停止追加补投，消费循环检查停止标记；完整的执行超时、优雅停止与 RUNNING 恢复仍属于第三、四节。

新增 4 项队列恢复测试并扩展独立 Worker 进程测试：

- 只补投超时 PENDING，其他七状态与新任务不受影响；补投后更新时间防止紧接着重复扫描。
- 真实 BLPOP 后模拟数据库领取失败，补投后成功执行，重复消息不重复写入。
- 补投响应丢失、标记回写失败后仍可重试；三次投递仅一次执行，最终只有一条业务记录。
- 扫描后并发取消，不覆盖取消原因，不执行已取消任务。
- 独立 Worker 自动补投丢失的待领取任务，跳过非法 UTF-8 / 非 UUID / 不存在的任务消息，继续处理后续任务并正常停止。
