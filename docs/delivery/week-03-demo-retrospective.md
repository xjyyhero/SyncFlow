# Week 3 演示与复盘初稿

## 演示准备

按 [本地部署说明](../deployment/local-v1.0.md)启动。先展示 `docker compose ps -a`：五个常驻服务运行，mysql-init 正常退出；打开 Web 和 API `/docs`。使用新测试环境，避免历史任务混入演示。

## 建议演示顺序（约 8–10 分钟）

1. **架构与异步返回（1 分钟）**：说明 React → API 保存文件与 PENDING → Redis ID → 独立 Worker → MySQL → 页面刷新。API 返回 201 时无需等待 Worker；展示日志中的同一 job_id。
2. **正常导入（2 分钟）**：上传 `sample-valid.csv`，展示文件名/大小、提交按钮禁用、自动跳转。最终 SUCCESS、5/5/0；说明整数/一位小数金额转为两位，名称中的逗号未被拆列。
3. **部分成功与分页（2 分钟）**：上传 `sample-mixed.csv`，观察 PARTIAL_SUCCESS、22/1/21。进入错误页，展示行号、amount、AMOUNT_INVALID、原始行；第一页 20 条、第二页 1 条，最后物理行号 23。
4. **文件级失败（1 分钟）**：上传 `sample-invalid-header.csv`，FAILED、0/0/0。即使失败行数为 0 也能进入错误页，行号 `-`、原因 CSV_HEADER_INVALID。
5. **数据库和权限（1 分钟）**：说明成功数据在 sync_records、错误在 sync_errors；API/Worker 共享 uploads 卷，Worker 只读。不要现场破坏开发数据库制造故障，展示第七节真实 MySQL 约束失败测试证据即可。
6. **边界与验证（1 分钟）**：展示 74 项后端测试和浏览器报告，解释每 250 行事务、单批失败不撤销其他批、金额不能使用浮点近似、三个终态停止轮询。
7. **限制与后续（1 分钟）**：明确 BLPOP 无 ACK/崩溃自动恢复，预留重试/并发参数不生效，V1.1 以新 Issue 演进；第九节再完成 PR、标签和正式发布验收。

可讲解的规则修改示例：将临时验收环境的 `MAX_RECORDS_PER_JOB` 改小，重建 API/Worker，上传超限样例观察 FILE_TOO_MANY_ROWS，再恢复配置。此操作只针对可丢弃测试环境；正式演示默认用已验收配置，不临时改代码。

## 复盘初稿

| 问题 | 本周处理 | 后续改进 |
| --- | --- | --- |
| Week 1 提案与实际 API 状态码/字段不同 | 统一共享响应模型，运行时导出 OpenAPI；第七节修正测试计划 | 继续以可执行契约校验文档 |
| 文件级与行级失败计数容易混淆 | 文件错误空行号且失败行数为 0；页面为文件失败保留入口 | 明确运维查询与统计展示口径 |
| CSV 金额、日期、标识边界多 | Decimal、严格日期与 ASCII 标识；单元及真实 MySQL 边界验证 | 新业务规则配套边界用例 |
| 单批写库故障不能撤销之前成功数据 | 每 250 行事务，真实唯一约束/CHECK 故障测试、持久化进度核对 | 设计任务恢复与补偿流程 |
| 页面轮询可能在离开后继续请求 | 取消旧请求、清理定时器；受控浏览器时钟验证 | 进一步处理弱网和后台标签页策略 |
| OpenAPI 示例丢失 null | 生成后恢复显式示例，验证文件级错误示例完整 | 关注框架升级后的行为，保留回归 |
| 子测试失败可能被报告为通过 | 修复报告归类并添加自检 | 报告与 CI 结果保持一致 |
| 前期运行依赖本机目录/缓存 | 源码包白名单、依赖锁、内容校验、解压目录与全新卷复现 | 后续制定正式制品仓库、镜像版本与 CI 发布 |

这是一份演示与复盘初稿；实际讲解时补充个人分工、时间投入和现场问题。不要将本地通过描述为已完成生产部署、性能保障或正式发布。
