# Week 1 工作清单

本周目标：理解需求、完成技术设计、搭建可运行的项目骨架，并走通首次 PR 交付流程。本周不要求完成 CSV 导入等完整业务功能。

依据：[产品需求说明书](product-requirements.pdf)、[第 1 周任务文档](week-01.pdf)。

## 一、需求理解

- [x] 阅读 PRD，明确项目目标、用户角色和当前版本范围。
- [x] 整理需求疑问清单，标注“待确认 / 已确认”，记录确认结论及依据。
- [x] 整理业务名词表，统一任务、同步、幂等、Worker 等概念。

产出见 [需求理解](requirements-understanding.md)；已完成需求整理，未明确的业务规则仍保留“待确认”。前五项实测记录见 [交付记录](week-01-first-five.md)。

## 二、技术设计

- [x] 选择后端技术栈：Python + FastAPI（沿用原 README 选择）。
- [x] 绘制系统边界图，明确 Web、API、Worker、MySQL、Redis 的职责，区分 HTTP 同步调用与 Redis 异步消息。
- [x] 绘制从 CSV 上传到任务结束的核心流程图，包含正常路径和主要异常分支。
- [x] 使用 OpenAPI 3.x 编写 API 设计，包含请求方法、路径、参数、响应、状态码和错误码。
  - 业务接口统一使用 `/api/v1/` 前缀。
  - 成功响应使用 `{ "data": ..., "meta": ... }`。
  - 失败响应使用 `{ "error": { "code": ..., "message": ..., "details": ... } }`。
  - 错误码使用大写下划线字符串，列表分页参数使用 `page`、`page_size`。
  - 创建任务快速返回，响应不暴露内部路径、SQL、堆栈或连接信息。
- [x] 编写数据库设计，列明表、字段、类型、约束、索引及索引用途。
  - 任务、成功记录、错误记录、执行尝试分表。
  - 金额使用 `DECIMAL`；时间使用 `datetime(3)` 存储 UTC。
  - 任务主键使用 UUID 或 ULID 字符串；业务数据表可使用自增主键。
  - 每张表包含 `created_at`、`updated_at`。
  - 同一任务内的业务标识设置唯一约束；关联在应用层维护，不强制数据库外键。
  - 明确迁移管理方式，确保重复执行迁移安全。
- [x] 明确 MySQL 事务边界、Redis 队列与 Worker 异步处理方案。
- [x] 设计任务状态机，明确状态、合法转换及触发条件。
- [x] 设计 Web 页面、路由、核心交互，以及加载、空数据和请求失败时的展示。
- [x] 编写测试计划，覆盖正常、异常、边界场景，区分单元测试、MySQL 集成测试和前端交互测试。
- [x] 在设计中体现安全、日志与任务追踪、流式或分批处理、分页等非功能要求。
- [x] 检查 API、数据库、状态机、页面和测试设计是否一致，确保核心需求可追溯到接口、数据结构和测试场景。
