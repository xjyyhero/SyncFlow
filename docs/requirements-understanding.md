## 1. 项目目标

SyncFlow 是本地可运行的数据同步与任务管理服务。用户通过网页上传 CSV，系统创建任务并异步处理，将合法记录写入 MySQL，保留处理统计、错误明细及执行日志，供用户查询。

它解决人工录入效率低、脚本导入难追踪、失败原因不清和重复导入缺少保护的问题。

核心流程：上传 CSV → 校验请求和文件 → 在 MySQL 保存任务 → 投递到 Redis → Worker 处理 → 校验并写入合法记录、保存错误记录 → 更新统计与最终状态 → 网页展示结果。

依据：PRD 第 2、3、6 节。

## 2. 用户角色

| 角色 | 主要需求 |
| --- | --- |
| 数据操作人员 | 上传 CSV、创建任务、查看状态与统计、查看错误明细 |
| 系统维护人员 | 查看日志、定位失败任务、重试任务、维护运行环境和升级服务 |

角色用于理解使用场景。项目不实现登录和权限控制，所有功能对访问者开放。维护人员的“重试”场景不意味着第一周需要实现重试功能。

依据：PRD 第 5 节。

## 3. 版本与本周范围

### V1.0 最低要求

- Web、API、Worker、MySQL、Redis 均可在本地启动。
- 网页支持创建任务，异步处理 CSV，查询任务列表、详情及错误明细。
- 正确处理正常文件、空文件、错误表头、字段错误和重复业务标识。
- 合法记录写入 MySQL，错误记录可查询，同一任务内相同业务标识不重复写入。
- 前端具备任务列表、创建任务、任务详情和错误明细页面，处理加载、空数据和请求失败状态。
- 有数据库迁移、基础单元测试和 API 集成测试。
- 通过分支、PR 和 AI Code Review 交付。

### V1.1 增强方向

- 可配置重试策略和执行记录。
- 幂等键与文件摘要冲突检测。
- 任务取消。
- CI 自动执行格式化、静态检查、测试和构建。
- 成功记录与错误明细 CSV 导出。
- 性能或故障恢复测试报告、完整发布说明及复盘。

### Week 1 交付范围

- 完成需求疑问、名词表、边界与流程、API、数据库、状态机、页面及测试设计。
- 搭建五个服务的可运行骨架，提供环境配置、健康检查及 README。
- 提交首个 PR 并完成 Review 流程。
- 完整 CSV 导入、重试、取消和导出不属于第一周的业务实现要求；相关后续能力需要在设计阶段考虑。

依据：PRD 第 10 节；Week 1“本周目标”“任务”“产出物”“验收标准”。PRD 总体要求与版本划分之间的细节差异，见疑问清单。

## 5. 业务名词表

下表为基于文档的统一理解；不替代后续任务文档的精确字段与状态定义。

| 名词 | 本项目中的含义 |
| --- | --- |
| SyncFlow | 数据同步与任务管理服务的名称。 |
| CSV | 承载待导入记录的表格文本文件；已提供四列合法示例，完整字段与编码限制待确认，详见 CSV 示例与字段说明。 |
| 同步／导入 | 本项目核心场景中，将 CSV 中合法业务记录写入 MySQL 的过程；文档未要求双向同步。 |
| 任务（Job） | 一次导入工作的可追踪单元，具有任务 ID、状态、统计及关联结果。具体创建规则待接口文档明确。 |
| 任务 ID（job_id） | 用于查询任务、关联记录和追踪日志的唯一标识，任务主键使用 UUID 或 ULID 字符串。 |
| Web | 用户操作界面，负责上传、发起请求和展示任务及结果。 |
| API | 前端与后端之间的 HTTP 接口，负责请求校验、任务创建和查询等。 |
| 异步处理 | 创建任务的请求快速返回，实际文件处理由后台独立执行。 |
| Redis 队列 | 在 API 与 Worker 之间传递待处理任务的机制；具体队列实现属于技术设计。 |
| Worker | 后台消费任务并执行 CSV 校验、数据写入和结果更新的进程。 |
| 文件级校验 | 针对整个文件的检查，例如空文件、表头、大小等。 |
| 行级校验 | 针对单条业务记录的检查，例如必填字段、字段格式及业务标识是否合法。 |
| 成功记录 | 通过校验并成功写入数据库的业务数据。 |
| 错误记录 | 用于查询和定位处理问题的记录，具体字段由后续设计确定。 |
| 业务标识 | 用来识别一条业务数据的字段；样例的 external_id 是候选业务标识，其正式去重含义仍待确认，同一任务内要求唯一。 |
| 状态机 | 描述任务有哪些状态，以及在什么条件下允许转换的规则。 |
| 部分成功 | 部分记录成功、部分记录失败的任务结果概念；精确判定条件待确认。 |
| 执行尝试（Attempt） | Worker 对任务的一次执行；重试会产生新的执行尝试。 |
| 重试 | 遇到允许重试的错误后再次执行任务；错误分类和策略待具体文档明确。 |
| 退避 | 重试前等待一定时间的机制，用于避免持续立即重试。 |
| 幂等 | 相同操作重复发起时，不因重复请求产生额外副作用；本项目用于重复任务或数据保护。 |
| 幂等键 | 用来识别重复请求的键，其具体作用域、冲突与过期规则待后续文档明确。 |
| 文件摘要 | 根据文件内容计算的摘要，用于内容识别及冲突检测；具体算法和规则待设计。 |
| 去重 | 识别重复数据并防止重复写入，与请求级幂等保护的对象不同。 |
| 唯一约束 | 数据库强制保证指定字段组合不重复的规则，是并发场景下防重复写入的保护。 |
| 事务边界 | 一组数据库操作共同提交或回滚的范围；本项目需明确任务、数据及统计的更新边界。 |
| 健康检查 | /healthz 提供进程存活检查；可选的 /readyz 检查数据库和 Redis 等依赖是否就绪。 |
